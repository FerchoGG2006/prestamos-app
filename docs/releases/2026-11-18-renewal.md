# Renewal correction — 18 November 2026

This release contains only the tested renewal balance correction and its regression tests; no new desktop flows, route synchronization or customer-data migrations are included. Renewal capital outflow is new principal minus prior balance (net cash plus paperwork), independent of historical loan order; the renewed credit is inserted first consistently with origination.

Exact case: opening physical cash500000, prior debt620000; principal700000, total rate40%, paperwork35000 -> customer cash45000, physical cash420000, debt980000, Admin1400000. Compensation is not collections. Reopening existing serialized data produces the same result without adding records.

Storage keys, persisted schema, application identifiers, Expo project/runtime, domains and installed binary identity are unchanged. No reset, import/restore or customer deletion runs during this correction. OTA delivery uses the existing preview/production branches and existing web production alias. This does not require uninstalling the phone application.

The existing Actions publisher was failing because latest EAS CLI dependencies need Node>=22; the runner is updated from20 to22 and isolated financial regressions now run before publication.


## General-case verification before production

The isolated matrix passes 127 scenarios and 1,632 assertions: capital100k/350k/700k/1.25M, rates0/10/20/40%, zero/explicit/configured paperwork, disabled paperwork, configured rounding, regular and migrated credits, five payment frequencies, prior cash/Nequi payments, insufficient physical cash, historic ordering on reopen and successor renewal chains. It checks that P-S-F is the customer net, Base decreases by P-S including paperwork, Admin changes only by new interest, refinancing is not collection, exact retries do not duplicate credits, and metrics reads do not rewrite persisted bytes. Invalid inputs, paid/cancelled contracts, closed days and conflicting retries reject without writes. The existing mobile rule requiring positive net disbursement is preserved.

These checks exposed and corrected a zero-rate fallback, repeat-renewal duplication and clipping a negative cash ledger to zero. The corrected calculation shows the actual cash balance. No stored balances or historical records are silently rewritten.
