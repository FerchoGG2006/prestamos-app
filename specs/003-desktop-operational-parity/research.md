# Research decisions
## Recovery (research_recovery)
SQLite snapshots must be validated read-only, including integrity/FK/schema checks. Recover into a new empty office instead of replacing active Hikari DB; include managed attachments in package. Add startup office path override; no real restore executed. jpackage runtime currently lacks jdk.httpserver, and existing dist is stale; build into fresh dated folder. Installer ISCC path needs configurable discovery.
## Sync (research_sync)
Legacy mobile uses expectedAmount, ACTIVE/PAID/RENEWED/CANCELLED, DAILY/etc and assignedCollectorId. Snapshot includes already paid installments AND payments; blindly importing both double-applies. New loans lack desktop operationType; determine origination from LOAN_DISBURSEMENT movement; migration from explicit notes/no-disbursement, never invent cash. Existing mobile fetch sends no PIN header. Use a short-lived route-scoped capability URL generated by manager, which existing officeServerUrl accepts without UI changes. Real user's mobile remains untouched.
## Alternatives
Overwriting an open database, modifying mobile UI, silently editing historical balances and trusting client-supplied route are rejected. No unknown business formula remains.
